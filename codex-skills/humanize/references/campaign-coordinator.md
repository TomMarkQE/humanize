# Native App campaign coordination

Use this protocol when a repository already defines a campaign's run files, candidate boundary, evaluator, and terminal decisions. The task package remains authoritative for workload, correctness, scoring, evidence fields, review triggers, and promotion or no-go. Use its run state and scheduling rules; do not create a parallel `.humanize/rlcr` state, Stop hook, or nested Codex CLI process.

## Delegate execution; retain decisions

The root thread reads the task contracts and current run state, fixes the next hypothesis and evidence boundary, assigns bounded work, checks decision-relevant evidence, and writes decisions, round state, and scoreboard in the task's existing files. After compaction or resumption, load only the current phase, candidate/base identity, score, blockers, and next action; follow evidence links when they affect the decision. Once a Goal Plan is accepted, use it without rereading its generation inputs. Chat history is supplementary.

Delegate **all evidence-heavy phases** to bounded execution children: readiness diagnosis, reference calibration, baseline and A/A runs, noise or warmup diagnosis, candidate implementation, correctness and final validation, evaluator scripts, raw data collection, and local retries. Name each assignment's question, exact inputs and paths, allowed writes, stopping bound, designated result report, and handoff criterion. The same executor may finish a coherent diagnosis and its bounded retries; spawn a **fresh** Implementer for each new mechanism hypothesis. Keep one candidate writer per worktree.

A child writes its own result report and permitted raw artifacts; the root writes the task's decisions and run state, not a transcription of child reports. A Reviewer writes only its own designated report and otherwise operates read-only. A Profiler writes only task-designated diagnostic artifacts and its report, never candidate code.

Use `fork_turns: "none"` and pass task contracts and exact evidence paths rather than conversation history. Set actual `model` and `reasoning_effort` spawn fields only when the caller or project explicitly chooses them; otherwise omit both to inherit the runtime choice. If requested fields are unavailable, report the capability block. Humanize supplies no model default.

Before a candidate attempt, record one falsifiable mechanism hypothesis, candidate/base identity, frozen workload, full task-required correctness gate, deciding metric, and evidence location. The Implementer owns code, local compile and tests, evaluators, and bounded repair in its run-owned worktree, recording failed rows as well as successes. A performance sweep starts only after one candidate configuration passes every condition of the task's full correctness gate; earlier configuration changes serve correctness diagnosis rather than speed ranking. Machine-searchable parameters remain inside the mechanism attempt. The root selects mechanisms and retains the validated best separately from the active exploration candidate.

## Evidence handoff and review

Use concise child messages or waits for routine progress. The child report, usually summarized in 500–1000 tokens, identifies the role and attempt, exact tested candidate/base and artifacts, oracle and full-gate coverage, every acceptance-relevant failure, performance workload and timing scope when eligible, values with units and variance when available, resource effects, changed or inspected files, unresolved issues, and durable evidence paths. A review finding additionally names the tested file and lines, decision relevance, raw evidence, and verified or unresolved status. Keep detailed logs and per-row results in designated task artifacts. Never collapse an unmeasured case into a pass. If a child fails before reporting, retain its last known identity, error, and evidence path in the existing run records, then assign bounded recovery.

The root checks targeted code and evidence behind each decision and reconciles the report with task-owned records. Let execution children run scripts, inspect raw JSON and logs, and retry local failures; avoid duplicate validators or repeated raw-result polling in the root. The root may inspect raw evidence directly when a discrepancy or consequential claim requires it.

Request a **fresh independent Reviewer** at task-selected triggers: initial or materially changed evaluation contract; a material evidence contradiction or new synchronization/lifetime risk; and final promotion or whole-task no-go. Ordinary rounds, parameter sweeps, local repairs, and evidence-backed local attempt stops require no separate Reviewer by default. Give a Reviewer the immutable candidate/base snapshot, original task contracts, evaluator commands, evidence paths, and proposed focus; require independent checks of the triggered scope, correctness, comparability, and claimed impact. Review may overlap later work under the task's readiness and dependency rules, including bounded exploration from a correct, review-pending candidate when explicitly allowed.

A known blocking contract or correctness issue blocks dependent work. Pending required review leaves affected claims provisional: it cannot authorize terminal promotion or replace the confirmed best. Late blocking findings invalidate affected descendant claims and attempts; repair their evidence and task-defined counts in existing run records. Routine saves do not wait for review. Return local repair under an unchanged hypothesis and acceptance contract to the same Implementer; use independent recheck when the task's review trigger applies.

## Search and terminal decisions

Keep a compact decision summary in the task's existing iteration record: best and active candidates, ancestry, observed facts versus hypotheses, rejected directions and revisit triggers, and the next experiment. Link original round decisions and raw evidence instead of duplicating them. A correct but slower candidate may continue under the task's bounded experiment criteria; it does not replace the best or qualify for promotion.

Apply the task's stagnation policy to its **valid, evaluable attempts**, not only attempts with individual reviews. Information gained is distinct from metric improvement. When a premise is contradicted or the task's threshold is reached, compare continuing the mechanism with a structural alternative and choose the smallest experiment that could change the decision. An evidence-backed local stop is not campaign completion and does not need a mandatory Reviewer. Apply the task's final promotion or whole-task no-go gate, including required independent final review; a child verdict or compact summary alone cannot close the campaign.
